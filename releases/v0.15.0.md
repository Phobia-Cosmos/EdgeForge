# EdgeForge 0.15.0 LoP retention evidence development snapshot

- 日期：2026-08-23
- 状态：development snapshot；不是部署稳定版，也不是 LoP 科学结论
- 范围：固定预算 probe 的 old-task retention 对照、metric-role 分离、矩阵 preflight 与版本归档

## 实现

- `scripts/brainuicl-fixed-budget-probe.py` 新增可选 `--retention-data-root` 与重复的 `--retention-subject` 参数。probe 在当前任务训练批次上执行 Adam 更新，在 retention 批次上只执行 `eval`；每个曲线记录 retention loss/ACC/MF1，并计算 initial/final/gain/AULC、ACC/MF1 drop 和 loss delta。
- `scripts/run-raeeg-lop-matrix.py` 的 compact manifest 支持 `retention` 对象：`data_root`、`subjects`、`max_files`、`batch_size`。输入预检验证旧任务目录和对应 label 文件，probe command 才会接收 retention 参数。
- bundle merger 将 `task.forgetting.*` 与 `task.probe.retention.*` 标成 `metric_role=retention`；其余 instrumentation/probe/unlabeled 指标继续分别标为 predictor/outcome/diagnostic。
- trajectory catalog 的 grouping identity 增加 split 与 retention design digest；同一 seed 下不兼容的旧任务集不会被拼成一条轨迹。
- `summarize-raeeg-lop-matrix.py` 增加 retention 指标列和 `metric_roles` schema，缺失值保持 null。
- instrumentation 增加 `checkpoint-optimizer-provenance-v1`，仅对候选 optimizer/moment/scheduler 文件记录 path/size/SHA-256，永不反序列化；没有这类文件的当前 BrainUICL milestone checkpoint 明确返回 `unavailable`。
- probe 将 Adam lr、weight decay、update steps 和 `state_persisted=false` 写入 optimizer diagnostic；该状态不被解释为 checkpoint 的完整 optimizer trajectory。

## 证据边界

Retention drop 只描述“这次新任务 probe 前后旧任务集的变化”。它不是完整 continual-learning BWT（没有替代完整 task stream 的最大历史性能定义），也不是 LoP predictor/outcome。LoP 仍使用同一新任务、同一预算下 checkpoint 与 fresh 的 plasticity gap，并要求真实多 seed、匹配 stage grid 和独立反事实。
