# EdgeForge 0.11.0 候选验证

- 日期：2026-08-21
- 范围：Target Probe、可移植 model pipeline 与版本化 RA-EEG LoP 分析基座
- 版本：`0.11.0`
- 状态：candidate，等待 Orange Pi 真实 probe 与 Runtime 验证

## 自动化验证

执行：`PYTHONPATH=src python3 -m unittest discover -s tests -v`

结果：`97/97` 通过。

覆盖：Target Probe CLI、无 Backend 推断策略、真实 `/dev/rknpu*` 门槛、Backend/Target Registry 既有边界、correctness false failure gate，以及在独立临时 `work_root` 中执行 packaged reference adapter 的 `export → transform → compile → run → correctness → benchmark` 六阶段回归。

模型级 regression API/CLI 已加入，验证了 Backend/Target 隔离、失败 run 不作为 baseline、compile/steady latency 阈值和 HTTP 查询路径。

部署目标证据审计 `target-audit` 已加入，覆盖 probe digest 完整性、目标架构匹配、显式 Backend advertisement、required accelerator 和同 manifest digest 的 correctness 运行匹配。审计在缺少模型运行或仅有 inferred Backend 时返回 `blocked`，不把硬件型号/驱动文件当作部署成功。

控制面新增 `POST /api/v1/deployment-audits`，发布自动化可以提交同一组 manifest/probe/evidence 做即时检查；接口不会把原始 Probe 或 EEG 写入 Artifact Store。

模型 pipeline stage provenance events 已加入，验证了 stage 事件的结构化耗时、exit code、输出摘要和 API 查询。

`lop-lagged-correlation-v1` 已加入，覆盖按有序 checkpoint stage 的 lag 配对、Pearson/Spearman、确定性 seed-cluster percentile bootstrap、exact context、最新 task 指标隔离、内容寻址 SQLite/API/CLI 持久化和幂等创建事件。回归测试确认不同 workload/protocol/comparison group/method、不同 transition/context grid、重复 seed、缺失 pair 和常量指标都不能得到 `ok`。

只读 `lop-audit` CLI 已加入，能够直接扫描本地 catalog 并按方法报告 source、ER predictor、plasticity outcome、stage、seed 和 replay 证据状态；缺少 predictor 或 source 的历史结果不会被误判为 LoP。

在当前本地 catalog 上，EWC、Online-EWC、SI、MAS、Finetune 都有 `plasticity.acc_gain`，但没有 ER predictor；BrainUICL、SPR、PuriDivER 的登记 source 路径不存在。使用 `task.importance.mean` 作为自定义 predictor 时，五种方法都只有 seed 4321，因此统一为 `insufficient-seeds`，仅作探索性覆盖检查。

随后对 BrainUICL 工作区全部 672 个 `metrics.json`/`RESULTS.json` 完成只读审计：所有文件均缺少 `task.spectra.transformer_1.effective_rank`。其中 EWC 209、Plain-ER 95、SI/MAS 各 68、Online-EWC 65、Finetune 61 个结果有 plasticity outcome，但仍不能据此判断 LoP。

## 当前证据边界

本机 x86_64 已成功执行 `target-probe` 和 synthetic model pipeline。该结果只验证控制面/Worker 接口，不是 Orange Pi 部署证据，也不是 BrainUICL 模型性能。

共享 `research` 环境的 PyTorch `2.11.0+cu130` 下，`config/model-pipeline-torch-eager.json` 与 `config/model-pipeline-torch-compile.json` 均在 CPU 上完成六阶段；`torch-compile` 使用 `backend=eager` 作为本机编译 contract，未宣称 CUDA 性能。

当前尚未写入 Orange Pi ARM64 probe、ONNX/IREE/RKNN Runtime correctness、真实模型离线 EEG inference 或板端性能数据。因此本版本保持 candidate，不创建稳定发布结论。IREE contract 继续 blocked，不下载 LLVM/IREE 源码，不填充伪造 source identity、binary 或 benchmark。

LoP 分析器不改变现有实验的科学状态。当前真实 LoP 数据仍只有 seed 4321，状态继续是 `blocked-by-checkpoint`；分析结果无论 status 是否为 `ok` 都固定 `scientific_conclusion_allowed=false`，只允许解释为描述性关联，不允许宣称因果机制。
