# EdgeForge 0.7.0 发布记录

- 开发日期：2026-08-16
- 状态：硬件验证通过
- 阶段：V7 RA-EEG Experiment Contract

## 目标

把本机已有 EEG 持续学习实验和新的真实 checkpoint LoP Probe 纳入 EdgeForge 的版本化任务、Artifact、指标和日志系统，同时保留算法协议与硬件能力边界。

## 当前实现

- `ExperimentSpec`、`ExperimentBundle` 和 `raeeg-metrics-v1` adapter。
- `experiment_run` command/import 两种模式。
- `experiment_runs`、`experiment_metrics`、实验 API/CLI 和结构化事件。
- 八实验本地 Catalog 与批量导入脚本。
- 真实 BrainUICL checkpoint 固定预算 Plasticity/Spectrum/Norm Probe。
- 原始 EEG 不上传、工作根目录约束和命令白名单。

## 自动化与真实验证

- EdgeForge 自动化测试：46/46 通过。
- BrainUICL LoP Probe 单元测试：2/2 通过。
- Python compileall 与 `git diff --check`：通过。
- V6 数据库迁移：原有 4 个 Worker、9 个 task、9 条 Benchmark、6 个 Artifact、1 条 tuning run 和 1 条 schedule decision 全部保留；V7 增加空的 experiment tables 和 0.7.0 release，不改写旧记录。

## 本地历史实验导入

通过 0.7.0 控制面与真实 `worker-4070s` import task 导入 8 个已有实验，共归一化 8326 条研究指标：

| Comparison group | 实验 |
|---|---|
| `aligned-full49` | BrainUICL、Finetune、EWC、Online EWC、SI、MAS |
| `method-transfer` | SPR-EEG、PuriDivER-EEG |

aligned 组的数据库摘要恢复了真实 `final_old_acc`、`final_seen_acc` 与 `bwt_acc`；例如 BrainUICL 为 `0.732575 / 0.676196 / +0.013943`，Finetune 为 `0.606467 / 0.548944 / -0.094082`。SPR/PuriDivER 保持独立 protocol 和 comparison group，不做跨协议排名。

## 真实 ISRUC LoP Probe

EdgeForge 通过共享 BrainUICL 环境在 RTX 4070 SUPER 上执行真实 checkpoint Probe：

| 验证 | checkpoint stage | next subject | ACC gain | Transformer ER |
|---|---:|---:|---:|---:|
| 单阶段 smoke | 0 | 64 | +0.050000 | 10.602827 |
| 多阶段 smoke | 0 | 64 | +0.050000 | 10.602827 |
| 多阶段 smoke | 10 | 91 | -0.050000 | 8.972979 |
| 多阶段 smoke | 25 | 10 | 0.000000 | 7.755772 |

单阶段 Bundle digest 为 `5ec675f19c5cff41fa78a36c73aa58226d31fc71b2379cd34d23119cf0861e28`；多阶段 Bundle digest 为 `75c28f47f1c17589ca1abe9b6b0ce4a8d3c6d0693e352f8ad2b25e7dc39c467c`。多阶段小样本得到 ER 与 future plasticity Pearson `0.570474`，但只有 3 个 stage、4 条 sequence 和 1 个 update step，因此只验证计算与持久化链路，禁止作为科研结论。

## 失败记录与修复

Preflight 的第一次 LoP task 失败：Worker 将共享虚拟环境 Python 符号链接解析为 `/usr/bin/python3.12`，导致 `torch` 不可见。V7 修复为“使用解析目标做白名单验证，但保留原 venv launcher 执行”，并增加回归测试。Preflight 数据库保留 1 failed + 9 succeeded；最终数据库为 10/10 succeeded，没有删除失败历史。

## 已知边界

- release smoke 的单 stage、单步小样本结果只证明链路可运行，不构成 LoP 科研结论。
- aligned-full49 六方法与 SPR/PuriDivER method-transfer 使用不同 comparison group，系统不宣称它们可直接排名。
- V7 不执行 checkpoint promote/reject/rollback；Capability Gate 计划在 V8 实现。
