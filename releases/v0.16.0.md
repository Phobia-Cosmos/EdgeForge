# EdgeForge 0.16.0 ARM target setup development snapshot

- 日期：2026-08-24
- 状态：development snapshot；不是 ARM 部署稳定版，也不是 RKNN/NPU correctness 结论
- 范围：AI compiler IR/Backend 边界说明、Orange Pi/P550 用户目录级配置、RKNN runtime 证据扩展

## 实现

- `scripts/configure-arm-target.py` 默认执行只读 inventory；显式 `--apply` 创建用户目录、环境模板、Worker 启动脚本和 target manifest；`--sync-source` 只同步 EdgeForge 源码并排除 `.git`、原始数据、checkpoint、日志、Artifact 和缓存。
- 配置器将 Orange Pi 固定为 `aarch64` CPU/reference profile，将 P550 固定为 `riscv64` reference/build profile；两个模板均只广告 `python-reference`，不写入 token，也不自动启动 Worker。
- `target_probe` 增加 RKNN runtime file evidence，并检查 `/dev/rknpu*`；共享库、demo 或 DRM 节点不会单独解锁 `rknn`。
- AI 编译器说明明确分开 EdgeForge `OperatorSpec`、PyTorch `torch.export` Graph IR 和后端 lowering；当前 `brainuicl.pt2` 作为导出证据保存，但模型 compile adapter 尚未将同一文件直接交给 IREE/RKNN/ONNX。

## ARM 实际配置

- Orange Pi：SSH inventory ready；`aarch64`、Cortex-A55/A76、8 cores、约 15.96 GiB；配置和源码同步成功，远端 `import edgeforge` 成功。现有 `librknnrt.so`、`librknn_api.so` 和 demo model；没有 `/dev/rknpu*`，Python 没有 `rknn`/PyTorch/ONNX Runtime，RKNN 保持 blocked。
- P550：SSH inventory ready；`riscv64`、4 cores、约 25.98 GiB；配置和源码同步成功，远端 `import edgeforge` 成功；仅广告 `python-reference`。
- 两个目标均执行真实 `python-reference` `matmul[16,16,16]` fp32 smoke，correctness 均为 true 且 checksum 相同；本次 median 约为 Orange Pi `1.014 ms`、P550 `3.002 ms`，仅作为协议/语义验证，不作为跨 ISA 性能排名。
- 未安装未知系统包、未复制真实凭证、未启动远端 Worker；启动前仍需配置控制面 URL/token，并通过对应 correctness gate。
