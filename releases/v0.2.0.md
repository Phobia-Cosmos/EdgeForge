# EdgeForge 0.2.0 发布记录

- 开发日期：2026-08-10
- 状态：硬件验证通过
- 阶段：V2 Operator Benchmark Framework

## 目标

确保所有后续版本均具有不可覆盖的版本清单、运行日志、任务事件和硬件 Benchmark 记录，并开始从普通远程任务转向结构化 AI Operator workload。

## 当前实现

- JSONL 路径：`EDGEFORGE_LOG_DIR/v0.2.0/{control,worker,cli}/<run-id>.jsonl`。
- SQLite 结构化数据：`events`、`releases`、`tasks.version`、`tasks.runtime_version`、`benchmarks`。
- Operator IR：name、shape、dtype、backend、attrs。
- Reference Backend：MatMul、Softmax、RMSNorm、SiLU correctness 与重复耗时采集。
- 查询入口：CLI 与 `/api/v1/events`、`/api/v1/releases`、`/api/v1/benchmarks`。

## 自动化与硬件验证

- 单元、存储、Worker、版本与 HTTP 集成测试：22/22 通过。
- Python compileall：通过。
- 本机端到端验证：版本化 control/worker/cli JSONL、事件查询、发布查询和 Benchmark 查询均通过。
- 四节点矩阵：4 个 Operator × 4 个 Worker，共 16 个任务，correctness 16/16 通过。
- 所有 Performance Database 记录均同时保存 `version=0.2.0` 和 `runtime_version=0.2.0`。

## 已知边界

Reference Backend 使用 Python `float` 做确定性 correctness 基线；当前 `fp16` 和 `bf16` 是 IR/调度元数据，尚未模拟具体低精度舍入。真实精度与加速性能必须由后续硬件 Backend 提供。
