# EdgeForge 0.6.0 发布记录

- 开发日期：2026-08-11
- 状态：硬件验证通过
- 阶段：V6 Compiler-aware Scheduler

## 目标

使用 Performance Database、Kernel Registry 和 Worker 实时状态，为一个 Operator 自动选择 Kernel、Backend 与 Worker，并持久化可解释的成本估算和调度原因。

## 当前实现

- 基于 exact Worker、same architecture 和 unseen fallback 的三级历史成本估计。
- latency、compile time 与实时 Worker load 的可配置目标函数。
- Kernel/Backend/Worker 硬约束过滤和确定性候选排序。
- `compiler-plan` dry-run、`compiler-run` 自动执行和 `schedule-decisions` 查询。
- `schedule_decisions` 数据库与 `scheduler.decision` 结构化事件。
- 执行结果回流 Benchmark 数据库，使下一次 Plan 使用新增样本。

## 自动化与迁移验证

- 自动化测试：40/40 通过。
- Python compileall 与 `git diff --check`：通过。
- V5 数据库迁移：原有 1 个 release、1 个 Kernel、3 条 Benchmark、30 条 event、3 个 task、3 个 Artifact 和 1 条 tuning run 全部保留；V6 仅增加当前 release 与空的 `schedule_decisions` 表。

## 自动路由验证

默认策略 `compile_weight=0.05`、`load_weight_ms=1.0` 生成 5 条可解释候选。Planner 选择 `worker-4070s + kernel-triton-matmul-autotune-v1`：预计 latency 0.015008 ms、compile 258.957 ms、load penalty 0.033625 ms、总 objective 12.996483 ms；第二名 x86 Reference objective 为 13.292775 ms。

`compiler-run` 按该决策执行成功，correctness PASS，实测 median 0.013280 ms，并写入一条 Benchmark 和一条 schedule decision。再次 dry-run 后，Triton exact-worker 样本数从 1 增加到 2，估计 compile time 更新为 129.523 ms，objective 更新为 6.520794 ms，仍选择同一路径。
