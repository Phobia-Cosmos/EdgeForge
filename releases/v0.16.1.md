# EdgeForge 0.16.1 RK3588 accelerator validation snapshot

- 日期：2026-08-24
- 状态：development snapshot；GPU OpenCL 与 RKNN board-runtime smoke 已通过，Vulkan Mali ICD 尚未配置；不是 EEG 模型部署稳定版，也不是科学结论
- 范围：对照 Orange Pi 官方用户手册 §3.37，修正 RK3588 DRM NPU 识别，增加离线 GPU/NPU API smoke 和 capability preflight

## 实现

- `src/edgeforge/accelerator_probe.py` 提供无摄像头的 OpenCL、Vulkan loader/device、RKNN C API probe；`edgeforge accelerator-smoke` 可在已同步的板端直接运行，`scripts/rk3588-accelerator-smoke.py` 额外支持本机和 SSH 运行，并将 JSON 与版本化 JSONL 日志分开保存。
- `target_probe.py` 增加 `rknpu_drm_driver`、`rknpu_platform`、`gpu_userspace`、`opencl_info` 和 `vulkan_loader` 证据；`runtime_capabilities` 区分 `rk3588_npu_device`（旧字符节点）与 `rk3588_npu_drm`/`rk3588_npu_platform`（当前 RK3588 布局）。
- `deployment_preflight.py` 的 `rknn` 要求板端 Runtime 文件和任一 NPU 设备证据，不再错误要求 `rknn_python`；`opencl`/`vulkan` 后端的能力要求也被显式化。
- `rknn`/`opencl`/`vulkan` preflight 增加只读 `--runtime-validation` 输入：没有已记录 API smoke 时保持 `BLOCKED`，实际 smoke 的 `npu.status=pass` 和各 RKNN API step 成功后才可 PASS。
- Worker 的 accelerator inventory 识别 `/sys/class/drm/*/device/driver=RKNPU`，但 `backend_claims.inferred` 和默认 Worker backend 广告策略不变。

## 官方手册对应关系

手册第 3.37 节规定 RKNN-Toolkit2 在 Ubuntu PC 上完成模型转换，板端使用 `librknnrt.so`/`rknn_server` 或 RKNPU2 C API。EdgeForge 采用直接板端 C API 路径验证 Runtime；PC/ADB proxy 和摄像头 demo 不属于本 smoke 的前置条件。手册说明已归档在 `docs/rk3588-accelerator-validation-v1.md`。

## Orange Pi 实际结果

- 硬件/内核：RK3588 OPi 5 Ultra，`aarch64`，kernel `6.1.43-rockchip-rk3588`，8 cores，约 15.96 GiB。
- 用户态差异：官方手册示例是 Debian 11；本板实际为 Ubuntu 22.04.5 LTS，因此 `rknn_demo` 的依赖和 Vulkan 包不能仅按手册截图假设已安装。
- GPU OpenCL：`Mali-G610 r0p0`、ARM OpenCL 3.0、4 compute units；离线 256-element FP32 vector-add max absolute error `0.0`，status `pass`。
- Vulkan：loader `libvulkan.so.1` API `1.3.204` 可加载；没有 Vulkan ICD JSON，`vkCreateInstance` 返回 `-9 (VK_ERROR_INCOMPATIBLE_DRIVER)`，status `blocked`。
- NPU：DRM `/dev/dri/card1` 与 `/dev/dri/renderD129` 映射到 `RKNPU`，platform devices `fdab0000.npu`/`rknpu_dev.10.auto` 存在。系统 `/usr/lib/librknnrt.so`（API `1.4.0`）和用户缓存 RKNPU2 v1.5.2 fallback 都能加载 RK3588 `mobilenet_v1.rknn`，driver 均为 `0.9.6`；3 次零输入 `init/query/run/output` 成功且输出 SHA-256 一致。默认系统 Runtime run median 约 `2.20 ms`，v1.5.2 fallback 约 `1.94 ms`，仅验证 Runtime 执行/确定性，不是有标签模型 correctness。
- `/usr/share/rknn_demo/mobilenet_ssd.rknn` 在系统 Runtime 下返回 `Invalid RKNN format`，作为 demo model/version/target mismatch 留存，未覆盖系统文件。`rknn_server` 进程证据保留，但直接 C API smoke 不依赖 PC ADB proxy。

## 验证命令与归档

```sh
PYTHONPATH=src python3 -m unittest tests.test_accelerator_probe tests.test_target_probe tests.test_deployment_preflight tests.test_worker -v
PYTHONPATH=src python3 scripts/probe-target.py --name orangepi --ssh-host orangepi --version 0.16.1 --output .edgeforge/v0.16.1-target-probe-orangepi.json
PYTHONPATH=src python3 scripts/rk3588-accelerator-smoke.py --name orangepi --ssh-host orangepi --version 0.16.1 --repeat 3 --output .edgeforge/rk3588-accelerator-smoke-v0.16.1.json --log-dir logs
```

本版本产物包括 target probe、accelerator smoke JSON/JSONL、pytest/unittest 输出、官方手册摘录、命令清单和 `SHA256SUMS`，统一归档于 `logs/archive/v0.16.1/rk3588-accelerator-validation/`。`partial` 是当前预期结果：OpenCL 与 NPU 已验证，Vulkan ICD 需要由板卡镜像提供方补齐后才能转为全通过。
