# EdgeForge 0.3.0 发布记录

- 开发日期：2026-08-10
- 状态：硬件验证通过
- 阶段：V3 Kernel Registry 与性能回归基础

## 目标

把 V2 的 Operator/架构/耗时记录扩展为可区分 Kernel 实现的注册和比较系统，为 CUDA、Triton、RKNN、ARM 和 RVV Backend 提供统一登记协议。

## 当前实现

- KernelSpec：operator、backend、kernel version、architectures、dtypes、shape constraints、metadata。
- Kernel Registry：注册、查询和任务创建时的 Operator/dtype 兼容性检查。
- 调度过滤：领取任务前根据 Kernel 支持的架构过滤 Worker。
- 硬件指纹由 Worker 能力报告固定保存，避免不同 CPU 实现的 benchmark 混淆。
- Performance Regression：按 operator、shape、dtype、backend、kernel、architecture 比较相邻结果。

## 自动化与迁移验证

- 单元、存储、Worker、版本与 HTTP 集成测试：26/26 通过。
- Python compileall：通过。
- V2 SQLite 数据库迁移到 V3 schema 后，旧 release、event、task 和 benchmark 记录保持可查询。
- Kernel identity 与 kernel version 均有 Worker/Store 回归断言。
- 性能回归检测使用合成慢化样本验证，能按配置阈值返回回归项。

## 四节点硬件验证

注册 `kernel-softmax-x86-v1`、`kernel-softmax-arm-v1` 和 `kernel-softmax-riscv-v1` 三个架构专属 Kernel，并在四个 Worker 上执行 Softmax 1024、FP32、5 次重复运行：

| Worker | Kernel | 中位耗时 | Hardware fingerprint | 结果 |
| --- | --- | ---: | --- | --- |
| RTX 4070S 主机 | `kernel-softmax-x86-v1` | 0.094 ms | `eaeb7b44b6d5a9dbd5666468` | PASS |
| Orange Pi | `kernel-softmax-arm-v1` | 2.971 ms | `36d5fd5565c5407ea9251850` | PASS |
| P550 | `kernel-softmax-riscv-v1` | 1.382 ms | `fc8bfa3dc7171aa7e2b7461b` | PASS |
| Meles | `kernel-softmax-riscv-v1` | 1.396 ms | `443e2183166bddeab06ee118` | PASS |

四条 Benchmark 均保存 `version=0.3.0`、`runtime_version=0.3.0`、`kernel_version=1`，并具有四个不同硬件指纹。故意提交的 MatMul workload 与 Softmax Kernel 不兼容组合在控制面被拒绝，没有进入 Worker 队列。

## 已知边界

Kernel Registry 当前只保存元数据和兼容性，不上传或分发二进制 artifact。性能回归以同一 key 的相邻两次结果比较，尚未引入显式 baseline、warmup、统计置信度和噪声模型；这些属于 V4 Compiler/Artifact Backend。
